## 1. 개념 (8분)

### 1-1. 확률은 나왔다. 이제 무엇을 쓸까
GPT는 한 걸음마다 다음 [토큰](#tok01) 후보 전체에 확률을 매깁니다. 그다음 그중 **하나를 골라** 글에 붙이고, 다시 다음 걸음으로 갑니다. 오늘은 "어떻게 고르나"입니다.

[Day 12](#day12)의 **greedy**는 늘 1등만 고릅니다. 번역처럼 정답이 거의 하나인 일에는 좋습니다. 하지만 긴 글을 쓰게 하면 밋밋해지고 같은 말을 되풀이하는 경향이 있습니다. Holtzman 외(2020)는 확률이 가장 큰 글을 찾는 방법(greedy, [빔 서치](#day12))이 오히려 이렇게 **망가진 글**을 낸다고 보고했습니다.

### 1-2. 샘플링: 확률대로 제비뽑기
**샘플링**은 확률을 그대로 제비뽑기 비율로 씁니다. 후보 확률이 [0.67, 0.24, 0.09]라면 100번 뽑을 때 1등이 약 67번, 2등이 약 24번, 3등이 약 9번 나옵니다. 그래서 같은 질문에도 답이 조금씩 달라집니다.

문제는 꼬리입니다. 확률이 아주 작은 후보도 수만 개가 모이면 꽤 자주 뽑혀서, 엉뚱한 토큰이 끼어듭니다. 아래 세 가지 손잡이가 이것을 조절합니다.

### 1-3. 온도: 확신 다이얼
[Day 05](#day05) 도전 과제 (a)에서 만져 본 그 **temperature**입니다. 소프트맥스에 넣기 전에 점수를 **온도 T로 나눕니다.**

$$p = \text{softmax}(z / T)$$

- T < 1: 점수 차이가 커져 1등이 더 높아집니다. 막대가 **뾰족**해집니다
- T = 1: 원래 확률 그대로
- T > 1: 점수 차이가 줄어 막대가 **평평**해집니다. 낮은 후보도 자주 뽑힙니다
- T → 0: 1등이 확률 1에 다가가 greedy와 같아집니다

확신 다이얼이라고 생각하세요. 다이얼을 내리면 모델이 "1등 말고는 안 쓴다"고 고집하고, 올리면 "이것도 저것도 괜찮다"고 느슨해집니다.

> 같은 글자, 다른 뜻: [Day 04](#day04)의 $\hat T$에서 T는 **번역문**이었습니다($\hat T$는 모델이 고른 번역문). 오늘의 T는 **온도**(temperature)라는 숫자 하나입니다.

### 1-4. top-k: 위에서 k개만 남기기
확률이 큰 순서로 **k개만 남기고** 나머지는 0으로 만든 뒤, 남은 것을 다시 합이 1이 되게 나눕니다. Fan 외(2018)는 이야기를 쓰게 할 때 k = 10을 썼습니다.

약점은 k가 고정이라는 점입니다. 모델이 확신할 때(1등이 0.95)는 k개도 너무 많아 엉뚱한 후보가 섞이고, 헷갈릴 때(비슷한 후보가 20개)는 k개가 너무 적습니다.

> 같은 이름, 다른 대상: 나중에 11단계의 MoE 챕터에서도 top-k가 나옵니다. 거기서는 "확률이 큰 **전문가** k명을 골라 그 출력을 **모두 섞어** 씁니다". 오늘의 top-k는 "다음 **토큰 후보** k개를 남겨 그중 **하나를 뽑습니다**". 위에서 k개를 고르는 방법만 같고, 고르는 대상과 그다음에 하는 일이 다릅니다.

### 1-5. top-p: 누적 확률 p까지만 남기기
Holtzman 외(2020)의 **top-p**(nucleus 샘플링이라고도 함)는 개수 대신 **확률의 합**으로 자릅니다. 큰 것부터 막대를 하나씩 쌓다가, 쌓은 합이 **p에 닿거나 넘는 순간** 멈추고 거기까지만 남깁니다.

모델이 확신하면 한두 개만, 헷갈리면 여러 개가 남습니다. 남는 개수가 상황에 맞게 저절로 바뀌는 것이 top-k보다 나은 점입니다.

### 1-6. 순서와 쓰임새
보통 순서는 **온도로 막대 모양 바꾸기 → top-k나 top-p로 자르기 → 남은 후보에서 뽑기**입니다.

| 하는 일 | 흔히 쓰는 출발점 | 이유 |
|---|---|---|
| 사실 질문, 코드, 계산 | 온도 낮게 (0~0.3) | 답이 거의 하나. 매번 같은 답이 좋음 |
| 이야기, 시, 아이디어 | 온도 0.7~1 + top-p 0.9 안팎 | 다양함이 좋되 엉뚱한 꼬리는 자름 |

서비스와 모델마다 기본값은 다르니 표의 숫자는 출발점으로만 보세요. 그리고 **확률이 높다고 사실인 것은 아닙니다.** 모델이 틀린 내용에 높은 확률을 주면, 온도 0은 그 틀린 답을 매번 똑같이 냅니다. (모델이 그럴듯하게 지어내는 문제는 나중에 RAG 챕터에서 다룹니다.)

## 2. 예제 따라하기 (6분)

**쓸 값:** 점수 z = [2, 1, 0]. e ≈ 2.718, e² ≈ 7.389, e⁴ ≈ 54.6, $e^{0.5}$ ≈ 1.649

**1. 온도 T = 1.** e^z = [7.389, 2.718, 1], 합 11.107 → **[0.67, 0.24, 0.09]** ([Day 05](#day05) 예제와 같음)

**2. 온도 T = 0.5.** z/T = [4, 2, 0] → [54.6, 7.389, 1], 합 63.0 → **[0.87, 0.12, 0.02]**. 1등이 더 높아졌습니다.

**3. 온도 T = 2.** z/T = [1, 0.5, 0] → [2.718, 1.649, 1], 합 5.367 → **[0.51, 0.31, 0.19]**. 평평해졌습니다.

(2번과 3번은 반올림 때문에 합이 1.01로 보입니다. 반올림 전에는 정확히 1입니다.)

**4. top-k (k = 2).** 확률 [0.5, 0.3, 0.15, 0.05]에서 위 2개만 남김 → 합 0.8로 나눔 → **[0.625, 0.375]**

**5. top-p (p = 0.9).** 같은 확률에서 큰 것부터 쌓기: 0.5 → 0.8 → **0.95**. 0.95가 0.9를 넘었으니 3개에서 멈춤 → 합 0.95로 나눔 → **[0.53, 0.32, 0.16]** (이것도 반올림 때문에 합이 1.01)

## 3. 능동 연습 (10분)

아래 실습 위젯에서 "오늘 날씨가 ___" 다음 토큰 6개의 확률 막대를 보며 온도, top-k, top-p를 움직여 보세요. 잘린 후보는 흐리게 바뀝니다. "10번 뽑기"로 T = 0.2와 T = 1.5의 결과를 비교하고, 마지막에 상황별 설정 문제를 풀어 보세요.

### ✏️ 손계산 (e ≈ 2.718, e⁴ ≈ 54.6)
1. 점수 [2, 0], 온도 T = 2일 때 1등의 확률은? (소수 둘째 자리까지)
2. 점수 [2, 0], 온도 T = 0.5일 때 1등의 확률은?
3. 확률 [0.4, 0.3, 0.2, 0.1]에 top-k (k = 2)를 쓰면?
4. 같은 확률에 top-p (p = 0.8)를 쓰면 몇 개가 남고, 다시 나눈 확률은?
5. 확률 [0.92, 0.05, 0.02, 0.01]에 top-p (p = 0.9)를 쓰면 몇 개가 남나요?
6. 온도를 0에 아주 가깝게 내리면 어떤 방법과 같아지나요?
7. 사실을 묻는 고객 상담 챗봇과 시를 쓰는 앱. 온도를 더 높게 둘 쪽은?

### 🧩 미니 챌린지
확신할 때의 확률 [0.92, 0.05, 0.02, 0.01]과 헷갈릴 때의 확률 [0.3, 0.25, 0.2, 0.15, 0.1]이 있습니다. top-k (k = 3)와 top-p (p = 0.85)는 각각 몇 개를 남기나요? 어느 쪽이 상황에 맞게 움직이나요?

### 💻 코드 (선택)
```python
import numpy as np
def softmax(z): e = np.exp(z - z.max()); return e / e.sum()

z = np.array([2.0, 1.0, 0.0])
for T in [1, 0.5, 2]:
    print(T, softmax(z / T).round(2))          # [0.67 0.24 0.09] / [0.87 0.12 0.02] / [0.51 0.31 0.19]

p = np.array([0.5, 0.3, 0.15, 0.05])         # 큰 순서로 정렬돼 있다고 가정
k = 2
print((p[:k] / p[:k].sum()).round(3))         # top-k → [0.625 0.375]
n = np.searchsorted(np.cumsum(p), 0.9) + 1    # 누적 합이 0.9에 닿는 자리까지
print(n, (p[:n] / p[:n].sum()).round(2))      # top-p → 3 [0.53 0.32 0.16]
print(np.random.choice(n, size=10, p=p[:n] / p[:n].sum()))   # 10번 뽑기
```

## 📝 한 줄 정리
샘플링은 확률대로 제비를 뽑고, 온도는 막대를 뾰족하게(낮게)·평평하게(높게) 만들며, top-k는 개수로, top-p는 누적 확률로 엉뚱한 꼬리를 잘라 낸다.
