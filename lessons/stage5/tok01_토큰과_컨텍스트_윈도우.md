## 1. 개념 (8분)

### 1-1. 지금까지 대충 넘어간 말: 토큰
[Day 03](#day03)에서 "Je t'aime beaucoup &lt;EOS&gt;"를 **4토큰**이라고 불렀습니다. [Day 07](#day07)과 [Day 08](#day08)에서도 "토큰별 크로스엔트로피", "전체 토큰 수"라고 썼습니다. 그때는 "토큰 ≈ 단어 하나"로 읽어도 충분했습니다.

정확히는, **토큰**은 모델이 글을 읽고 쓰는 **조각 하나**입니다. 단어일 수도, 단어의 일부일 수도, 문장 끝 표시 &lt;EOS&gt; 같은 특수 기호일 수도 있습니다. 모델은 글자를 직접 보지 않습니다. 글을 토큰으로 자르고, 토큰마다 번호를 붙이고, 그 번호로 [임베딩](#day02) 행렬의 한 열을 꺼냅니다. 글을 토큰으로 자르는 도구를 **토크나이저**라고 합니다.

### 1-2. 단어 단위의 문제: 사전에 없는 단어
Seq2Seq 논문은 출력 어휘를 단어 **80,000개**로 정했고([Day 05](#day05)의 80,000칸 소프트맥스, [Day 12](#day12)의 빔 서치가 고르던 그 단어들), 나머지는 모두 `UNK`(모르는 단어)로 바꿨습니다([논문 코스](#course-seq2seq)의 논문 사실 카드). 사람 이름, 새로 생긴 말, 드문 활용형은 전부 `UNK` 하나로 뭉개집니다. 번역에 `UNK`가 나오면 그 자리는 비어 버립니다.

그럼 글자 단위로 자르면? 모르는 단어는 사라지지만, 문장 하나가 수백 토큰이 되고 글자 하나에는 뜻이 거의 없어서 모델이 할 일이 많아집니다.

### 1-3. 서브워드: 레고 덩어리
가운데 길이 **서브워드**(단어 조각)입니다. 자주 쓰는 단어는 통째로 한 토큰, 드문 단어는 아는 조각 몇 개로 나눕니다.

레고를 떠올리세요. 자주 만드는 모양은 미리 붙여 둔 덩어리로 보관하고, 처음 보는 모양은 덩어리와 작은 블록을 조립해 만듭니다. 그러면 **어휘 크기는 정해 둔 만큼만** 쓰면서도 **어떤 단어든** 쓸 수 있습니다.

### 1-4. BPE: 가장 자주 붙어 나오는 쌍을 합친다
Sennrich 외(2016)는 서브워드를 만드는 데 **BPE**(바이트 쌍 인코딩)를 썼습니다. 원래 파일 압축 방법이었습니다. 규칙은 단순합니다.

1. 모든 단어를 글자로 쪼갭니다.
2. 붙어 있는 두 토큰 쌍마다 몇 번 나오는지 셉니다(단어가 5번 나오면 그 안의 쌍도 5번).
3. 가장 많이 나온 쌍을 하나로 합쳐 새 토큰으로 삼습니다. **동점이면 먼저 나온 쌍**을 합칩니다.
4. 정해 둔 횟수만큼 2~3을 반복합니다.

합친 쌍은 순서대로 기록해 둡니다. 새 글을 자를 때도 이 순서대로 합칩니다. 어휘 크기 = 처음 글자 수 + 합친 횟수입니다(특수 기호가 있으면 그만큼 더). GPT-2의 어휘 50,257개는 바이트 256개 + 합치기 50,000번 + 특수 기호 1개입니다.

### 1-5. 컨텍스트 윈도우: 책상 넓이
**컨텍스트 윈도우**는 모델이 한 번에 볼 수 있는 토큰 수의 상한입니다. **입력과 출력을 합친** 수입니다. 책상 위에 펼쳐 둔 것만 보며 일하는 사람과 같아서, 책상이 꽉 차면 무언가를 치워야 합니다. GPT-3(2020)의 윈도우는 2,048토큰이었습니다. 지금 모델들은 훨씬 길지만 한계는 여전히 있습니다.

왜 한계가 있을까요? [셀프 어텐션](#sa01)은 모든 토큰이 다른 모든 토큰과 점수를 냅니다. 토큰이 1,000개면 1,000 × 1,000 = 100만 개의 점수입니다. 길이를 2배로 늘리면 점수는 **4배**가 됩니다.

길다고 다 잘 쓰는 것도 아닙니다. Liu 외(2024) "Lost in the Middle"은 긴 입력의 **가운데**에 둔 정보를 모델이 처음이나 끝에 둔 정보보다 덜 활용하는 경향을 보고했습니다.

> 토큰 수는 토크나이저마다 다릅니다. 영어 글을 많이 보고 만든 토크나이저는 한국어를 더 잘게 자르는 경우가 많아서, 같은 뜻의 글도 언어에 따라 토큰 수가 달라집니다. 정확한 수는 그 모델의 토크나이저로 직접 세어 봐야 합니다.

## 2. 예제 따라하기 (6분)

**쓸 값:** Sennrich 외(2016) 알고리즘 1의 단어와 빈도

| 단어 | low | lower | newest | widest |
|---|---|---|---|---|
| 나온 횟수 | 5 | 2 | 6 | 3 |

**0. 글자로 쪼개기.** 토큰 수 = 3×5 + 5×2 + 6×6 + 6×3 = **79**

**1. 쌍 세기.** e+s는 newest(6)와 widest(3)에 있어 **9**, s+t도 **9**, w+e는 lower(2) + newest(6) = **8**, l+o와 o+w는 low(5) + lower(2) = **7**.
e+s와 s+t가 동점입니다. 규칙대로 **먼저 나온 e+s**를 합칩니다 → `es`. newest와 widest에서 한 토큰씩 줄어 79 − 9 = **70**.

**2. 다시 세기.** 이제 es+t가 **9**로 1등 → `est`. 토큰 수 **61**.

**3.** l+o와 o+w가 7로 동점 → 먼저 나온 l+o → `lo`. 토큰 수 **54**.

**4.** lo+w가 7로 1등 → `low`. 토큰 수 **47**.

네 번 합쳐 `est`와 `low`라는 조각이 생겼습니다. 이제 이 단어 목록에 **한 번도 없던** 단어 "lowest"가 와도 l-o-w-e-s-t를 같은 순서로 합치면 `low` + `est`, **2토큰**으로 읽습니다. `UNK`가 없습니다.

**토큰 예산.** 윈도우 8,000토큰에 시스템 지시 500 + 붙여 넣은 문서 6,000 = 6,500. 답에 쓸 수 있는 것은 최대 8,000 − 6,500 = **1,500토큰**.

> (선택) 논문의 실제 코드는 단어 끝에 표시 `</w>`를 붙입니다("low"의 끝 w와 "lower" 가운데의 w를 구별하려고). 그러면 t+`</w>`도 9가 되어 세 쌍이 동점입니다. 오늘은 단순하게 이 표시를 뺐습니다.

## 3. 능동 연습 (10분)

아래 실습 위젯의 첫 화면에서 위 예제의 합치기를 직접 해 보세요. 가장 많이 나오는 쌍을 누르면 칩이 합쳐지고 토큰 수가 줄어듭니다(동점인 쌍은 어느 쪽을 눌러도 정답). 두 번째 화면 "책상 넓이"에서는 지시, 문서, 답의 길이를 바꾸며 윈도우가 넘치면 어떻게 되는지 보세요.

### ✏️ 손계산
단어와 빈도: hat 4번, cat 6번, cats 3번, at 2번
1. 글자로 쪼갰을 때 전체 토큰 수는?
2. 가장 많이 나오는 쌍과 그 횟수는?
3. 2번의 쌍을 합친 뒤 전체 토큰 수는?
4. 그다음에 합칠 쌍은? 합친 뒤 "cats"는 몇 토큰인가요?
5. 윈도우 4,000토큰, 시스템 지시 300, 문서 2,500. 답에 쓸 수 있는 최대 토큰은?
6. 토큰 2,000개에 셀프 어텐션을 하면 점수는 몇 개? 토큰이 4,000개가 되면 몇 배?
7. 위 예제의 합치기 4번을 마친 뒤, 새 단어 "newer"(n-e-w-e-r)는 몇 토큰으로 읽히나요?

### 🧩 미니 챌린지
어휘를 아주 작게(글자만) 하면 무엇이 나빠지고, 아주 크게(단어 수백만 개) 하면 무엇이 나빠질까요? 1-2, 1-3, 1-5를 근거로 한 가지씩 써 보세요.

### 💻 코드 (선택)
```python
from collections import Counter
words = {"low": 5, "lower": 2, "newest": 6, "widest": 3}
vocab = {tuple(w): c for w, c in words.items()}          # 글자로 쪼개기
for step in range(4):
    pairs = Counter()
    for w, c in vocab.items():
        for a, b in zip(w, w[1:]):
            pairs[(a, b)] += c                            # 단어 빈도만큼 세기
    best = max(pairs, key=pairs.get)                      # 동점이면 먼저 나온 쌍
    new = {}
    for w, c in vocab.items():
        out, i = [], 0
        while i < len(w):
            if w[i:i+2] == best: out.append(w[i] + w[i+1]); i += 2
            else: out.append(w[i]); i += 1
        new[tuple(out)] = c
    vocab = new
    print(best, pairs[best], sum(len(w) * c for w, c in vocab.items()))
# ('e','s') 9 70 / ('es','t') 9 61 / ('l','o') 7 54 / ('lo','w') 7 47
```

## 📝 한 줄 정리
모델은 글을 토큰이라는 조각으로 읽고, BPE는 가장 자주 붙어 나오는 쌍을 합쳐 조각을 만들어 처음 보는 단어도 읽게 하며, 컨텍스트 윈도우는 입력과 출력을 합친 토큰 수의 상한이다.
