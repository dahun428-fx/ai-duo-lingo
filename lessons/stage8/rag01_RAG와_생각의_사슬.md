## 1. 개념 (8분)

### 1-1. 오픈북 시험
언어 모델의 지식은 모두 **가중치 안에** 들어 있습니다. 그래서 세 가지 약점이 있습니다.

- 학습이 끝난 뒤의 일을 모른다
- 우리 회사 문서처럼 본 적 없는 것을 모른다
- 모르면서 그럴듯하게 **지어낸다** (환각이라고 부릅니다)

사람도 외워서만 보는 시험에서는 기억이 흐릿하면 틀린 답을 씁니다. 해법은 **오픈북 시험**입니다. 책을 찾아보고 답하게 하는 것. 이것이 **RAG**(검색 증강 생성)입니다.

### 1-2. RAG의 세 걸음
1. **찾기.** 질문과 관련 있는 문서 조각을 창고에서 찾는다
2. **붙이기.** 찾은 조각을 질문과 함께 모델의 입력에 넣는다
3. **답하기.** 모델이 그 조각을 읽고 답한다

왜 문서를 통째로 넣지 않고 조각낼까요? 모델이 한 번에 읽을 수 있는 글의 길이에는 한계가 있기 때문입니다. 그래서 문서를 미리 몇 문단씩 잘라 둡니다. 책을 통째로 건네지 않고 필요한 쪽만 복사해 주는 것과 같습니다.

새 지식을 넣으려고 모델을 다시 학습시킬 필요가 없습니다. (2020년 논문은 찾는 부분과 답하는 부분을 함께 학습시켰지만, 요즘은 이미 학습된 모델을 그대로 두고 쓰는 경우가 많습니다.) 창고의 문서만 바꾸면 새 지식을 쓸 수 있고, 어느 문서를 보고 답했는지 **출처**도 보여 줄 수 있습니다.

### 1-3. 찾기는 벡터로
"관련 있는 문서"를 어떻게 찾을까요? 낱말이 겹치는지만 보면 "자동차"와 "승용차"를 놓칩니다. 그래서 **뜻**을 벡터로 바꿉니다.

- 미리: 문서 조각마다 [임베딩](#day01) 벡터를 만들어 저장해 둔다 (벡터 창고)
- 질문이 오면: 질문도 같은 방법으로 벡터로 바꾼다
- 질문 벡터와 각 문서 벡터의 [내적](#day01)을 구해, **가장 큰 k개**를 고른다 (k는 몇 개를 가져올지 우리가 정하는 수입니다)

RAG는 내적이 클수록 관련이 깊다고 봅니다. 벡터의 길이가 같다면 내적이 크다는 것은 방향이 비슷하다, 곧 뜻이 가깝다는 뜻이었습니다. (길이가 다르면 긴 벡터가 유리해지므로, 실제로는 길이를 1로 맞춰 쓰는 경우도 많습니다.) 도서관 사서가 질문을 듣고 가장 가까운 서가로 걸어가는 것과 같습니다. 2020년 RAG 논문은 위키백과 전체를 이런 벡터 창고로 만들었습니다.

### 1-4. 생각의 사슬: 풀이를 쓰게 하기
두 번째 방법은 더 단순합니다. 모델에게 **답만 말하지 말고 풀이 과정을 쓰게** 합니다.

> 질문: 사과가 23개 있었습니다. 20개를 쓰고 6개를 더 샀습니다. 몇 개인가요?
>
> 바로 답하기: "27개" (틀림)
>
> 생각의 사슬: "23개에서 20개를 쓰면 3개. 6개를 더 사면 3 + 6 = 9. 답은 9개." (맞음)

2022년 논문은 프롬프트(모델에게 주는 입력 글)에 **풀이가 달린 예시 몇 개**를 넣어 주기만 했습니다. 그러자 큰 모델이 수학 문장제를 훨씬 잘 풀었습니다. 가중치는 하나도 바꾸지 않았습니다.

### 1-5. 왜 통할까
[GPT](#bg01)는 한 번에 토큰 하나를 쓰고, 그때까지 **쓴 글 전체**를 다시 봅니다. 풀이를 쓰면 중간 결과("3개")가 글로 남고, 다음 걸음은 그것을 **읽고** 이어 갑니다. 암산 대신 연습장에 적어 가며 푸는 것과 같습니다.

두 방법의 공통점: **모델의 입력에 필요한 것을 넣어 준다.** RAG는 필요한 지식을, 생각의 사슬은 중간 계산을 넣습니다.

조심할 점
- RAG는 찾은 문서가 틀렸거나 엉뚱하면 답도 틀립니다
- 풀이가 그럴듯하다고 정답이라는 보장은 없습니다. 틀린 풀이도 유창하게 씁니다

## 2. 예제 따라하기 (6분)

**찾기.** 질문 벡터 q = [1, 2]. 창고에 문서가 세 개 있습니다.

| 문서 | 벡터 | q와의 내적 |
|---|---|---|
| ㄱ: 환불 규정 | [2, 1] | 1 × 2 + 2 × 1 = **4** |
| ㄴ: 배송 안내 | [1, 3] | 1 × 1 + 2 × 3 = **7** |
| ㄷ: 회사 연혁 | [−1, 1] | 1 × (−1) + 2 × 1 = **1** |

k = 2라면 내적이 큰 순서대로 **ㄴ, ㄱ**을 고릅니다. ㄷ은 버립니다.

**붙이기.** 모델에게 가는 입력은 이렇게 됩니다.

> 다음 자료를 보고 답하세요.
> [자료 1] 배송 안내 …
> [자료 2] 환불 규정 …
> 질문: 배송이 늦으면 환불되나요?

**생각의 사슬.** "한 상자에 연필이 12자루. 3상자를 사서 친구에게 10자루를 줬다. 남은 연필은?"

풀이: 12 × 3 = 36자루. 36 − 10 = **26자루**. 걸음이 두 개이고, 첫 걸음의 결과(36)가 둘째 걸음의 재료입니다.

## 3. 능동 연습 (10분)

### ✏️ 손계산
1. q = [2, 1], 문서 A = [1, 1], B = [3, 0], C = [0, 2]. 각 내적은?
2. 1번에서 k = 1이면 어느 문서를 고르나요? k = 2이면?
3. q = [1, −1], 문서 D = [2, 2], E = [1, −2]. 어느 쪽이 더 관련 있나요?
4. 생각의 사슬로 풀어 보세요. "버스에 15명이 타고 있었다. 정류장에서 7명이 내리고 4명이 탔다. 다음 정류장에서 절반이 내렸다. 남은 사람은?" 걸음마다 중간 결과를 쓰세요.
5. 다음 중 RAG가 특히 도움이 되는 질문은? (가) "어제 바뀐 우리 회사 휴가 규정은?" (나) "2 + 3은?"
6. RAG의 세 걸음을 순서대로 쓰세요.

### 🧩 미니 챌린지
RAG를 썼는데도 모델이 틀린 답을 했습니다. 어디에서 잘못됐을 수 있는지 세 걸음(찾기, 붙이기, 답하기)마다 하나씩 생각해 보세요.

### 💻 코드 (선택)
```python
import numpy as np
q = np.array([1, 2])
docs = np.array([[2, 1], [1, 3], [-1, 1]])    # ㄱ, ㄴ, ㄷ
scores = docs @ q
print(scores)                                  # [4 7 1]
top2 = np.argsort(-scores)[:2]                 # 점수가 큰 순서로 2개의 번호
print(top2)                                    # [1 0]  → ㄴ, ㄱ

names = ["환불 규정", "배송 안내", "회사 연혁"]
prompt = "다음 자료를 보고 답하세요.\n" + "\n".join(f"[자료] {names[i]}" for i in top2)
print(prompt)
```

## 📝 한 줄 정리
RAG는 관련 문서를 찾아 입력에 붙여 주고, 생각의 사슬은 풀이 과정을 쓰게 한다. 둘 다 가중치를 바꾸지 않고 입력을 잘 채워 모델을 더 잘 쓰는 방법이다.

3. X. 프롬프트에 풀이가 달린 예시를 넣기만 하면 됩니다.
4. 중간 결과가 글로 남아, 다음 걸음이 그것을 읽고 이어 갈 수 있기 때문입니다.
