## 1. 개념 (8분)

### 1-1. 이상한 실험: 입력을 거꾸로
논문은 영어 문장을 **뒤집어서** 넣었습니다. "a b c"를 "c b a"로요. 프랑스어 출력은 그대로 둡니다. 그랬더니

| | 그대로 | 뒤집기 |
|---|---|---|
| perplexity (낮을수록 좋음) | 5.8 | **4.7** |
| BLEU (높을수록 좋음) | 25.9 | **30.6** |

BLEU는 번역 점수입니다. 다음 레슨에서 배우니 오늘은 "높을수록 좋다"만 알면 됩니다. 모델은 한 글자도 안 바꿨는데 성적이 올랐습니다. 왜일까요?

### 1-2. 단어 사이의 거리를 세어 보자
영어 "a b c"가 프랑스어 "α β γ"로 번역된다고 합시다 (a↔α, b↔β, c↔γ). 모델은 입력을 다 읽고 나서 출력을 씁니다.

**그대로 넣을 때:** a b c → α β γ

| 짝 | 사이 스텝 수 |
|---|---|
| a → α | 3 |
| b → β | 3 |
| c → γ | 3 |

**뒤집어 넣을 때:** c b a → α β γ

| 짝 | 사이 스텝 수 |
|---|---|
| a → α | **1** |
| b → β | 3 |
| c → γ | 5 |

평균은 둘 다 3으로 같습니다. 하지만 뒤집으면 **첫 단어 짝이 바로 붙습니다.** [Day 11](#day11)에서 본 것처럼 가까운 관계는 배우기 쉽습니다. 문장 앞부분을 먼저 제대로 번역하게 되면, 그걸 발판으로 뒷부분도 배웁니다. 논문은 이를 "최소 시간 지연(minimal time lag)이 줄었다"고 표현합니다.

### 1-3. 번역을 고르는 문제
학습이 끝난 모델은 단어마다 확률을 내놓습니다. 우리가 원하는 것은 **문장 전체 확률이 가장 큰 번역**입니다. 그런데 단어가 80,000개, 길이가 10이면 가능한 문장은 $80000^{10}$개. 전부 계산해 볼 수 없습니다.

**Greedy(탐욕) 방법:** 매번 확률이 제일 큰 단어 하나만 고릅니다. 빠르지만, 처음에 좋아 보인 선택이 나중에 막다른 길일 수 있습니다.

### 1-4. 빔 서치: 후보를 B개 들고 간다
**빔 크기 B** = 계속 들고 갈 후보 문장의 수.

1. 지금 들고 있는 후보 B개 각각에 다음 단어를 붙여 본다
2. 새로 생긴 문장들의 확률(지금까지의 곱)을 계산한다
3. 그중 **상위 B개만** 남기고 나머지는 버린다
4. 후보가 `<EOS>`(문장 끝)로 끝나면 완성 문장으로 따로 둔다

B = 1이면 greedy와 같습니다. 길 찾기 앱이 경로 하나만 보는 것과, 유력한 경로 2~3개를 같이 따라가 보는 것의 차이입니다.

## 2. 예제 따라하기 (6분)

모델이 내놓은 확률이 다음과 같습니다.

**첫 단어:** 나는 0.6 · 저는 0.4

**둘째 단어:**

| 앞 단어 | 밥 | 빵 | 물 |
|---|---|---|---|
| 나는 | 0.4 | 0.35 | 0.25 |
| 저는 | 0.9 | 0.1 | 0 |

**Greedy (B = 1)**
- 첫 단어: 0.6 > 0.4 → "나는"
- 둘째 단어: "밥" 0.4 → "나는 밥" = 0.6 × 0.4 = **0.24**

**빔 서치 (B = 2)**
- 첫 단어: "나는"(0.6)과 "저는"(0.4) **둘 다** 남긴다
- 둘째 단어를 모두 붙여 본다

| 후보 | 확률 |
|---|---|
| 저는 밥 | 0.4 × 0.9 = **0.36** |
| 나는 밥 | 0.6 × 0.4 = **0.24** |
| 나는 빵 | 0.6 × 0.35 = 0.21 |
| 나는 물 | 0.6 × 0.25 = 0.15 |
| 저는 빵 | 0.4 × 0.1 = 0.04 |

- 상위 2개: "저는 밥"(0.36), "나는 밥"(0.24)

Greedy는 첫 걸음에서 "저는"을 버려서 0.36짜리 문장을 영영 못 찾았습니다. 빔 서치는 2등 후보를 살려 둔 덕에 찾았습니다.

> 실제 구현은 확률을 곱하는 대신 **로그 확률을 더합니다** ([준비 4](#prep04)). ln 0.4 + ln 0.9 ≈ −1.02, ln 0.6 + ln 0.4 ≈ −1.43. −1.02가 더 크니 순위는 같습니다.

### 논문의 결과 (표 1)
| 모델 (LSTM 5개 앙상블) | BLEU |
|---|---|
| 빔 크기 1 | 33.00 |
| 빔 크기 2 | 34.50 |
| 빔 크기 12 | 34.81 |

1 → 2에서 1.5점이 오르고, 2 → 12에서는 0.31점만 오릅니다. **빔 크기 2면 이득의 대부분을 얻습니다.** (앙상블은 따로 학습한 모델 여러 개의 예측을 평균 내는 방법입니다.)

## 3. 능동 연습 (10분)

### ✏️ 손계산
1. 길이 4인 문장 "a b c d" → "α β γ δ"를 **그대로** 넣을 때, 짝마다 사이 스텝 수는?
2. 같은 문장을 **뒤집어** "d c b a"로 넣을 때 네 짝의 스텝 수는? 평균은?
3. 첫 단어 A 0.7, B 0.3. A 다음은 X 0.6 / Y 0.4, B 다음은 X 1.0. Greedy가 고르는 문장과 그 확률은?
4. 3번에서 빔 크기 2라면 둘째 단어까지 본 뒤 남는 상위 2개 후보와 확률은?
5. 3~4번에서 greedy는 가장 확률 높은 문장을 찾았나요?
6. 단어 5개, 길이 3이면 가능한 문장은 모두 몇 개인가요?

### 🧩 미니 챌린지
빔 크기를 아주 크게 하면 언제나 더 좋은 번역이 나올까요? 논문 표 1의 숫자(2 → 12에서 0.31점)와 계산 시간을 근거로 생각해 보세요.

### 💻 코드 (선택)
처음 보는 문법이 있어도 괜찮습니다. 그대로 붙여 넣어 실행하고, 출력이 손계산과 같은지만 확인하세요.
```python
first = {"나는": 0.6, "저는": 0.4}
second = {"나는": {"밥": 0.4, "빵": 0.35, "물": 0.25},
          "저는": {"밥": 0.9, "빵": 0.1}}

B = 2
beam = sorted(first.items(), key=lambda kv: -kv[1])[:B]     # 상위 B개
cands = []
for w1, p1 in beam:
    for w2, p2 in second[w1].items():
        cands.append((w1 + " " + w2, p1 * p2))
for sent, p in sorted(cands, key=lambda kv: -kv[1])[:B]:
    print(sent, round(p, 2))        # 저는 밥 0.36 / 나는 밥 0.24
```
`B = 1`로 바꾸면 greedy 결과("나는 밥 0.24")가 나옵니다.

## 📝 한 줄 정리

**손계산**
1. 모두 **4** (a→α 4, b→β 4, c→γ 4, d→δ 4)
2. a→α **1**, b→β **3**, c→γ **5**, d→δ **7**. 평균 (1 + 3 + 5 + 7) ÷ 4 = **4**로 같습니다.

6. 5 × 5 × 5 = $5^3$ = **125개**

**미니 챌린지**
아닙니다. 후보를 늘릴수록 계산은 그만큼 느려지는데 이득은 빠르게 줄어듭니다(2 → 12에서 0.31점). 게다가 모델의 확률이 완벽하지 않아서, 확률이 더 높은 문장이 사람이 보기에 더 좋은 번역이라는 보장도 없습니다.

**퀴즈**
1. 문장 앞쪽 단어 짝이 아주 가까워져(거리 1) 그 관계를 먼저 쉽게 배우고, 그것이 나머지를 배우는 발판이 되기 때문입니다.
2. Greedy(탐욕) 디코딩
3. X. 상위 B개만 남기고 나머지는 버립니다. 전부 계산하는 것은 불가능합니다.
4. 1 → 2 (33.00 → 34.50, +1.5점). 2 → 12는 +0.31점입니다.
