# 7단계. 저랭크 근사와 LoRA

⏱ 30분 · 📄 논문 연결: Hu 외 (2021) "LoRA: Low-Rank Adaptation of Large Language Models". 선형대수 한 줄로 거대한 모델을 값싸게 고치는 방법

---

## 🎯 오늘의 목표
1. 큰 모델을 통째로 미세조정하는 것이 왜 부담스러운지 설명할 수 있다.
2. LoRA의 식 $W' = W + BA$를 작은 행렬로 손계산할 수 있다.
3. 랭크 r을 정했을 때 학습할 숫자가 몇 개로 줄어드는지 계산할 수 있다.

**복습 (1분):** m × n 행렬의 랭크 k 근사는 숫자 몇 개를 저장하나요? (답: k × (m + n + 1). [SVD와 PCA](#svd01))

---

## 1. 개념 (8분)

### 1-1. 문제: 모델이 너무 크다
[미세조정](#bg01)은 사전학습한 모델의 가중치를 내 데이터로 조금 더 학습시키는 것입니다. 그런데 GPT-3의 가중치는 1750억 개. 일(번역, 요약, 상담…)마다 1750억 개짜리 사본을 하나씩 만들어 저장하고 학습시키는 것은 너무 비쌉니다.

### 1-2. 관찰: 바뀌는 양은 단순하다
미세조정 전의 가중치 행렬을 W, 후를 W'이라 하면

$$W' = W + \Delta W$$

ΔW(델타 W)는 **바뀐 양**입니다. LoRA 논문의 가설: 새 일에 맞추는 데 필요한 변화 ΔW는 **랭크가 아주 낮다.** 즉 [SVD](#svd01)에서 본 "큰 조각 몇 개"로 충분하다.

수천 쪽짜리 백과사전을 새로 찍는 대신 **얇은 정오표 한 장**을 끼워 넣는 것과 같습니다.

### 1-3. LoRA: 두 개의 얇은 행렬
ΔW를 직접 배우지 않고, 얇은 행렬 두 개의 곱으로 둡니다.

$$\Delta W = B A$$

"d × k"는 세로 d줄, 가로 k칸이라는 뜻입니다. k는 이 층에 들어오는 숫자 수, d는 나가는 숫자 수입니다. 예를 들어 d = 1000, k = 1000, r = 8이면 A는 8 × 1000, B는 1000 × 8입니다. 가운데가 8칸으로 좁아지는 모래시계 모양입니다.

- W: d × k (원래 가중치, **얼려 둠**. 학습하지 않음)
- A: r × k (가로로 긴 얇은 행렬)
- B: d × r (세로로 긴 얇은 행렬)
- r: 랭크. 보통 1~64의 작은 수

BA는 d × k 크기지만 [랭크](#rk01)는 r을 넘지 못합니다. BA의 모든 가로줄이 A의 가로줄 r개를 섞어 만든 것이기 때문입니다. 학습하는 것은 **A와 B뿐**입니다.

### 1-4. 숫자 세기
| | 학습할 숫자 수 |
|---|---|
| 통째로 미세조정 | d × k |
| LoRA | r × (d + k) |

복습의 k × (m + n + 1)과 닮았습니다. 다만 글자가 바뀌었으니 주의하세요. 여기서 k는 랭크가 아니라 가로 칸 수이고, 랭크는 r입니다. SVD는 조각마다 특이값 1개를 따로 저장해서 +1이 붙습니다. LoRA는 그 크기를 A와 B 안에 넣어 두어서 +1이 없습니다.

d = k = 1000, r = 8이면 100만 개 대신 8 × 2000 = **16,000개**. 1.6%입니다. 논문은 GPT-3에서 학습할 파라미터 수를 **1만 분의 1**로, 학습에 필요한 GPU 메모리를 **3분의 1**로 줄였다고 보고합니다.

### 1-5. 세 가지 요령
1. **시작은 0에서.** B를 0으로, A를 작은 무작위 수로 시작합니다. 그러면 처음에 BA = 0이라 원래 모델과 **똑같이** 출발합니다
2. **계산은 따로, 결과는 더해서.** $W'x = Wx + B(Ax)$. 큰 행렬 W'를 만들지 않고 x를 A로 줄였다가(r칸) B로 다시 늘립니다
3. **다 배우면 합친다.** 학습이 끝나면 W + BA를 미리 계산해 하나로 합칠 수 있습니다. 쓸 때의 속도는 원래 모델과 같습니다

일마다 작은 (A, B) 한 쌍만 저장하면 되니, 큰 모델 하나에 "번역용", "요약용" 정오표를 **갈아 끼워** 쓸 수 있습니다.

## 2. 예제 따라하기 (6분)

W = [[1, 0], [0, 1]] (2 × 2), r = 1.

B = [[1], [2]] (2 × 1), A = [[3, 4]] (1 × 2)

**ΔW = BA** (B의 각 칸 × A의 가로줄)

| | × 3 | × 4 |
|---|---|---|
| 1 | 3 | 4 |
| 2 | 6 | 8 |

ΔW = [[3, 4], [6, 8]]. 둘째 줄이 첫째 줄의 2배라 랭크 1입니다.

**W' = W + ΔW** = [[1 + 3, 0 + 4], [0 + 6, 1 + 8]] = **[[4, 4], [6, 9]]**

**입력 x = [1, 1]을 넣으면**
- 합친 뒤: W'x = [4 + 4, 6 + 9] = **[8, 15]**
- 따로 계산: Wx = [1, 1]. Ax = 3 + 4 = 7. B × 7 = [7, 14]. 더하면 [1 + 7, 1 + 14] = **[8, 15]** ✓

**숫자 세기.** 이 작은 예에서는 W가 4개, LoRA가 2 + 2 = 4개로 같습니다. 행렬이 커져야 이득이 납니다. 768 × 768에 r = 4면 589,824개 대신 4 × 1536 = **6,144개**(약 1%).

## 3. 능동 연습 (10분)

### ✏️ 손계산
1. B = [[2], [1]], A = [[1, 3]]일 때 BA는?
2. 1번의 BA의 랭크는?
3. W = [[1, 1], [0, 1]]에 1번의 BA를 더한 W'는?
4. d = 1000, k = 1000, r = 4일 때 LoRA가 학습하는 숫자는 몇 개? 통째로 할 때의 몇 %인가요?
5. d = 4096, k = 4096, r = 16이면? (4096 × 4096 = 16,777,216)
6. 학습을 시작할 때 B가 모두 0이면 BA는? 이때 모델의 출력은 원래 모델과 어떤 관계인가요?

### 🧩 미니 챌린지
r을 키우면 표현할 수 있는 변화가 늘어나지만 학습할 숫자도 늘어납니다. r = d = k로 키우면 LoRA는 무엇과 같아지나요? 반대로 r이 너무 작으면 어떤 일이 생길까요?

### 💻 코드 (선택)
```python
import numpy as np
W = np.eye(2)                          # [[1, 0], [0, 1]]
B = np.array([[1.0], [2.0]])           # 2 × 1
A = np.array([[3.0, 4.0]])             # 1 × 2
x = np.array([1.0, 1.0])

dW = B @ A
print(dW, np.linalg.matrix_rank(dW))   # [[3. 4.] [6. 8.]] 1
print((W + dW) @ x)                    # [ 8. 15.]
print(W @ x + B @ (A @ x))             # [ 8. 15.]  따로 계산해도 같음

d, k, r = 1000, 1000, 8
print(r * (d + k), d * k, r * (d + k) / (d * k))   # 16000 1000000 0.016
```

## 📝 한 줄 정리
LoRA는 큰 가중치 W는 얼려 두고, 바뀌는 양을 얇은 두 행렬의 곱 BA(랭크 r)로만 배워서 학습할 숫자를 r × (d + k)개로 줄인다.
